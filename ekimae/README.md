# 梅田地下メシ — 梅田の地下で飲む店を探す

梅田の地下にある飲食店を、**フロアの平面図**と**タグ**で探すためのWebアプリ。
大阪駅前第1〜第4ビルから始めて、KITTE大阪「うめよこ」・バルチカ03・ルクア バルチカへ広げている。
ビルド不要の静的サイト（HTML / CSS / vanilla JS）。GitHub Pages などにそのまま置ける。

- リスト表示とマップ表示の切替
- ビル・フロア・タグ（立ち飲み / 座り飲み / カウンターのみ / 現金のみ / ランチあり …）の複合フィルタ
- 店名・よみ・カテゴリ・区画番号・自分のタグ・メモを横断するフリーワード検索
- 営業時間と定休日から「いま営業中」を判定
- お気に入り / 自分の★ / メモ / 自分のタグ / 訪問履歴（端末内に保存）
- 星評価は Google マップ等で見た値を手入力して記録（確認日つき）、ワンタップで Google マップ・食べログ検索を開く
- PWA 対応。スマホのホーム画面に追加するとアプリのように開ける

## 使い方（ローカル確認）

`fetch` を使うので、ファイルを直接開くのではなくローカルサーバ経由で開く。

```sh
cd ekimae
python3 -m http.server 8000
# → http://localhost:8000
```

## 公開（GitHub Pages）

`.github/workflows/pages.yml` が `main` への push で `ekimae/` を GitHub Pages に公開する。
初回のみリポジトリ設定が必要：

1. GitHub → Settings → Pages → **Source** を `GitHub Actions` にする
2. `main` に push すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
3. スマホの Safari / Chrome で開き「ホーム画面に追加」

公開リポジトリの場合、`data/stores.json` の内容は誰でも見られる。個人的なメモは
`stores.json` には入らず端末内だけに保存されるので、そのまま公開して問題ない。

## データの入れ方

店舗データは `data/stores.json`。項目の仕様は **[SCHEMA.md](SCHEMA.md)** に切り出してある。
現状 447 件。うち 443 件は公式フロア案内から取り込んだ `verified: true`、
残り 4 件は検索で拾っただけの `verified: false`（階・区画が未確認）。
入れ方は4つ。

1. **取り込みスクリプト** — 公式フロア案内の CSV / HTML からまとめて入れる（下記）
2. **アプリ上で1件ずつ追加** — 右上の「＋」。歩きながら登録するのに向く
3. **CSVで一括登録** — 右上「≡」→ CSV 欄に貼り付け。書式は `data/stores.template.csv` 参照。
   1行目の見出しから列を判別するので並び順は自由（店名・区画・業種・タグ・予算・営業時間・
   定休日・よみ・電話・URL・ビル・フロアに対応）。見出しに ビル / フロア が無いときは、
   CSV 欄の下で選んだビル・フロアに入る。ID は取り込みスクリプトと同じ規則で決まるので、
   同じ店を二度貼っても重複しない。取り込む前に1行目の解釈を確認する画面が出る
4. **`data/stores.json` を直接編集** — まとめて作るならこれが速い

### 取り込みスクリプト

公式フロア案内を4ビル分まとめて取りに行く場合：

```sh
cd ekimae
python3 tools/fetch_official.py --list     # 取得先URLの確認
python3 tools/fetch_official.py            # 取得して差分だけ表示（dry-run）
python3 tools/fetch_official.py --write    # stores.json に反映
```

ブラウザで保存した HTML を `in/b2_B2.html` のように置いてあるなら
`--skip-download` を付ければダウンロードを飛ばせる。
URL が変わって404になったら `tools/fetch_official.py` の `PAGES` を直す。

個別に流す場合：

```sh
cd ekimae

# CSV / TSV から（公式フロア案内のコピペやスプレッドシートを想定）
python3 tools/ingest.py --csv in/ekimae2_b2.csv --building 2 --floor B2 \
    --source official:ekimae2 --verified

# 保存した公式フロア案内の HTML から区画番号と店名の対を拾う（best-effort）
python3 tools/ingest.py --html in/ekimae2_b2.html --building 2 --floor B2 \
    --source official:ekimae2 --dry-run

# 検算（件数・確認済み率・エラー）
python3 tools/validate_stores.py
```

- 店名からカテゴリとタグ（立ち飲みなど）を自動推測する
- クリニック・金券ショップ・銀行などは既定で落とす（`--keep-non-food` で残す）
- ID は「ビル+フロア+店名」から決まるので、**同じ店を何度取り込んでも重複しない**。
  後から公式データを流し込めば、検索で入れた行が上書き更新される
- `--dry-run` は差分を出すだけ。HTML モードは取りこぼす前提なので必ず一度目視する

### 未確認データの扱い

駅前ビルは入れ替わりが激しいので、行ごとに「誰が確認したか」を持たせている
（`source` と `verified`）。未確認の店はアプリで**赤い「未確認」バッジ**が付き、
「未確認」フィルタで一覧できる。現地で合っていたら詳細画面の
**「現地で確認した」**を押すと、その端末では確認済みになる。

アプリで追加・編集した内容は端末内（localStorage）にたまる。
「≡」→ **stores.json 形式で書き出す** で全件を1ファイルに出せるので、それを
`ekimae/data/stores.json` に上書きコミットすれば、他の端末や他人にも同じリストが見える。

### マップの表示について

マップ表示は**公式の平面図そのもの**。`plans/blocks.json` の区画位置を使って、
店を図の上に点で置く。絞り込みに該当する店だけ色が付き、それ以外は薄い点で残るので、
「いまいるフロアのどこに、条件に合う店があるか」が一目で分かる。
該当が8件以下のフロアは店名も出す（多いと重なって読めないため）。

区画番号が図に見当たらない店は、図の下に区画番号順で並べる。

`pos`（簡易グリッドの座標）は平面図が無いフロア用の予備。いまは全フロアに
平面図があるので使っていないが、フィールドとしては残してある。

## 公式の平面図（`plans/`）

店の詳細の「平面図で見る」で開く、公式サイトのフロア平面図。
`plans/b{場所キー}-{フロア}.jpg` を置いておくとアプリが読む。
端末から取り込んだ画像（IndexedDB）があればそちらが優先される。

画像は公式サイトのものなので、公開リポジトリに置くかはそのつど確認すること。
**いまは入れる判断になっている**（`plans/*.jpg` はコミット済み）。

14フロアぶん揃っている。ファイル名は `planKey()` と同じ `b{場所キー}-{フロア}` で、
場所キーが文字列の施設もそのまま続けて書く（`bkitte-B1` / `bbar03-4F` / `blucua-B2`）。

### `plans/blocks.json`（区画番号 → 図の上の位置）

これは**座標だけ**なので、こちらはリポジトリに入れている。
`{"b4-B1": {"6": [0.38, 0.25], ...}}` の形で、値は画像の横幅・高さに対する割合。
これがあると、平面図を開いたときに「その区画はここ」の○印が自動で出る。

作り直すときは `python3 tools/plan_blocks.py`。番号の読み取りは機械ではやっていない
（詳しくはスクリプト冒頭のコメント）。検出条件を変えたら、
`--sheets` でコンタクトシートを作り直して番号の並びを読み直すこと。

## 星評価について

Google Places API は従量課金で、取得したデータの保存にも規約上の制限があるため使っていない。
代わりに、店舗詳細の「外部評価を更新」で見た値を手入力し、**確認日つきで記録**する方式にしている。
Google マップ側の生の数値が見たいときは「Googleマップ」ボタンで開く。

## 店のある場所（venue）

もとは大阪駅前第1〜4ビルだけだったので `building` は 1〜4 の数字だった。
梅田のほかの地下にも広げたので、いまは**数字と文字列が混ざる**。

| キー | 名前 | 略称 |
| --- | --- | --- |
| `1` `2` `3` `4` | 大阪駅前第1〜4ビル | 第1ビル … |
| `kitte` | KITTE大阪 うめよこ | うめよこ |
| `bar03` | イノゲート大阪 バルチカ03（2〜5F・約50店） | バルチカ03 |
| `lucua` | ルクア大阪 バルチカ | バルチカ |

**1〜4 を数字のまま残しているのは意図的**。店のIDは「場所＋フロア＋店名のhash」
（`b4-B1-c86200`）で決まるので、ここを文字列にすると既存357件のIDが全部変わり、
お気に入り・メモ・訪問履歴・仲間のレビューが全部外れる。

場所を足すときは `app.js` の `VENUES` と `tools/ekimae_data.py` の `VENUES` の
両方に同じキーで足す。店が1件も無い場所は絞り込みチップに出ない。

取り込みは今までと同じで、`--building` に数字の代わりにキーを渡すだけ。

```sh
python3 tools/ingest.py --csv in/kitte_B1.csv --building kitte --floor B1 \
    --source official:kitte --verified
```

## 画面の構成

軽快さを優先して、条件を「開いてから選ぶ」形をやめてある。

- **上**: 検索バーと「＋店を追加」だけ
- **その下**: 条件チップの横一列（常時表示）。選択中の条件はここに並び、その場で外せる
  - 「こだわり」を押すとシートが開き、ビル／フロア／種類／タグ／条件／並びを全部選べる
  - シートの中身は `#filters-holder` に畳んであり、開くときにシートへ移して閉じるときに戻す
- **下**: リスト／マップ／メニューのタブバー（親指で届く位置）
  - 埋め込み表示では `position: fixed` が文書全体を基準にしてしまうため、
    流し込みに戻したうえで本文より前へ移す（`detectEmbedded()`）

## 友だちと使う（合言葉と共有）

claude.ai の Artifact として開いたときだけ、記録を**仲間と共有**する。
入口で合言葉を聞き、一度通れば端末に覚えるので次からは聞かない。

| 種類 | 誰に見える |
| --- | --- |
| 店のデータ（追加・編集・削除） | 仲間みんな |
| 星（自分の評価）・訪問履歴 | 仲間みんな（誰の記録かも分かる） |
| お気に入り・メモ・自分タグ・ピン | 自分だけ（自分の端末どうしでは同期する） |

- 名前は入口で自分で決める。claude.ai のログイン名は使わない
  （招待の仕方によっては相手が「不在」として見えることがあるため）
- 合言葉は平文では持たず、指紋（SHA-256）だけを共有領域に置く
- メニューから名前と合言葉を変えられる

**合言葉は鍵ではなく「のれん」**。ページの中身はブラウザで読めるので、
本当の保護は Artifact 側の共有設定（誰に開くか）のほう。
仲間には Artifact の共有メニューから**編集できる権限**で招待すること。
リンクを渡しただけの人は、読めても書き込めない。

手元で動きを確かめるときは `testing/claude-mock.js` を
`<script>` で先に読み込むと、Artifact ランタイムの代役になる。

## データの保存場所

| 種類 | 保存先 | 共有される？ |
| --- | --- | --- |
| 店舗リスト（`stores.json`） | リポジトリ | される |
| アプリ内で追加・編集した店 | localStorage ＋ 共有領域 | 仲間に共有される |
| ★ / 訪問履歴 | localStorage ＋ 共有領域 | 仲間に共有される（誰のかも分かる） |
| お気に入り / メモ / 自分のタグ | localStorage ＋ 自分専用領域 | されない |

端末内のデータはブラウザのデータ削除で消える。「≡」→ **バックアップを書き出す** で
定期的に JSON に退避しておくとよい。複数端末で同期したくなったら、そのときに
Supabase などのバックエンドを足す。
