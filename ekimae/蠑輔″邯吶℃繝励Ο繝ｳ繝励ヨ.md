## これは何

「梅田地下メシ」。梅田の地下の飲食店を、フロアの平面図とタグで探すWebアプリ。
大阪駅前第1〜4ビルの357件が入っていて、ここに3施設を足したいところ。

ZIPの中身が本体。まず `ekimae/README.md` と `ekimae/SCHEMA.md` を読むこと。
設計の意図と判断理由はすべてそこに書いてある。

公開済みのアプリ: https://claude.ai/artifact/5sUtWcnH5HcBm7sWfvXX3v
（更新するときは、このURLを `url` として渡すこと。渡さないと別物が新規作成される）

## 今回やってほしいこと

以下3施設の店舗データと平面図を取り込む。器（`VENUES`）はもう作ってあるので、
`in/*.csv` を埋めて `tools/ingest.py` に流すだけ。

| キー | 施設 | 階 | 規模 | 公式 |
| --- | --- | --- | --- | --- |
| `kitte` | KITTE大阪「うめよこ」 | B1 | 17店 | https://osaka.jp-kitte.jp/shop/gourmet/shoplist04.jsp |
| `bar03` | イノゲート大阪「バルチカ03」 | 2F〜5F | 約50店 | https://barchica03.com/ |
| `lucua` | ルクア大阪「バルチカ」 | B2 | 未確認 | https://www.lucua.jp/floormap/b2.html |

```sh
cd ekimae
python3 tools/ingest.py --csv in/kitte_B1.csv --building kitte --floor B1 \
    --source official:kitte --verified
python3 tools/validate_stores.py
```

平面図の画像が取れたら `plans/{キー}-{階}.jpg` に置き、
`tools/plan_blocks.py` で区画番号の位置表を作る。
ただし**区画番号を振っていない施設はピンの自動配置ができない**ので、
その場合は平面図だけ置いて、ピンは手動（アプリ内の「ここだ！とピンを置く」）にする。
`app.js` の `BUNDLED_PLANS` に追加するのを忘れないこと。

## 設計上、壊さないでほしいこと

- **店のIDは「場所＋フロア＋店名のhash」で決まる**（`b4-B1-c86200`）。
  ここが変わると、お気に入り・メモ・訪問履歴・仲間のレビューが全部外れる。
  だから駅前ビルの場所キーは `1〜4` の**数字のまま**にしてあり、
  新しい施設だけ文字列キー（`kitte` / `bar03` / `lucua`）にしている。
  場所を足すときは `app.js` の `VENUES` と `tools/ekimae_data.py` の
  `VENUES` の**両方に同じキーで**足すこと。
- **`source` と `verified` は行ごとの出どころ管理**。裏が取れていない行は
  `verified: false` にしておくと、アプリで赤い「未確認」バッジが出て、
  現地で確認したら昇格できる。**推測で店名を埋めないこと。**
- **共有するもの**: 店のデータ、星、訪問履歴（誰のかも分かる）。
  **自分だけのもの**: お気に入り、メモ、自分タグ、平面図のピン。
- 平面図の画像は公式サイトのものなので、公開リポジトリに置くかは
  そのつど確認すること（いまは入れる判断になっている）。

## 動作確認

```sh
cd ekimae && python3 -m http.server 8000
```
Playwright + Chromium が使える（/opt/node22/lib/node_modules/playwright）。
390x844 のモバイル表示で確認すること。

注意（ハマりやすい点）:
- 下のタブバーは `.tabbtn`。`getByRole('button', {name:'マップ'})` では取りにくい
- 絞り込みは「こだわり」チップ（`.qchip--lead`）を押すとシートに出る。
  シートの中身は `#filters-holder` から移してきているので、
  閉じるときに戻さないと次に開いたとき空になる
- 詳細・追加フォームは `<dialog>` ではなく `#sheet` の中に描画される
- 共有機能を手元で試すには `testing/claude-mock.js` を先に読み込ませる
  （Artifactランタイムの代役。アプリ本体からは読み込んでいない）

Artifact公開用のページは `python3 tools/build_artifact.py` で index.html から生成する。
artifact.html を本体、styles.css / app.js / data/stores.json / plans/* を
supporting files として渡す。
